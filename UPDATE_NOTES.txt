==== Security audit: ALL findings (#1-#13) ====
Run:  python manage.py migrate     (accounts 0003)      Then, once:  python manage.py rotate_initial_passwords --yes
Test: python manage.py test accounts proctoring exams core     (new: accounts/test_security.py, proctoring/test_leave_lock.py SecurityPatchTests)
Environment (Render): NUM_PROXIES=1 (default 1 in production), DJANGO_SECRET_KEY (the server now refuses to start with the default key),
  optional TOKEN_TTL_HOURS=12, TEMP_PASSWORD_TTL_DAYS=14
#1  Starting password is a random 8-character code (accounts/temp_password.py), NOT the index number. It is derived from DJANGO_SECRET_KEY, so
    DO NOT CHANGE the secret key while sheets are in use (printed codes would stop matching). The credentials sheet / CSV prints it; the
    single "reset password" now also returns it once. Unused starting passwords expire after 14 days ("ask the office for a new one").
    Students already texted a password by the parents' SMS are not on the sheet (their SMS password stays valid).
    Existing accounts that never logged in still have the OLD index password until you run rotate_initial_passwords --yes (it skips the SMS ones).
#2  REST_FRAMEWORK NUM_PROXIES (default 1 in production, 0 for runserver/tests). golive_check now FAILS if it is 0.
#3  Live monitor sends masked parent numbers; "Show number" reveals one number and is audited (guardian.phone_reveal).
#4  /attempts/<id>/event/ throttled to 30/min per student.
#5  Locked students get question = null until an admin unlocks them.
#6  The exam page also reports blur (after 1.5 s without focus) and pagehide; each exit is reported once.
#7  GET /settings/ hides the four anti-cheat fields from non-admins.
#8  New core/middleware.py (nosniff, Permissions-Policy, strict CSP on JSON API replies, no-store); the rich-text sanitiser keeps only <img> whose
    src is /media/... on your own host (an image on another server would reveal the student's address); frontend/public/_headers has the
    front-end CSP (edit the API address; on Render copy the values into Settings -> Headers).
    Still true: the login token is kept in localStorage; a CSP is the mitigation.
#9  Login tokens expire after 12 hours (accounts/authentication.py).
#10 Question images get random file names (/media/ must stay public: <img> cannot send a login token). Old images keep their names.
#11 Unknown user names now get the same "too many attempts" lock-out as real ones, so the message cannot reveal which names exist.
#12 NOT changed: a classmate can still lock an account by failing on purpose (15 minutes). Fixing it means locking per device instead of per
    account, which would weaken the brute-force protection; an admin can see "login.locked" in the audit log.
#13 requirements.txt has upper bounds; the gunicorn server refuses to start with the default SECRET_KEY. (A pinned lock file needs
    internet: run  pip freeze > requirements.lock  on your computer after installing.)
